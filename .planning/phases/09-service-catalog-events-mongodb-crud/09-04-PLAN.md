<objective>
Close verification gap CR-01: `events._relative_time()` renders "unknown" instead of a real
relative-time string for every event read from the platform's own real in-cluster MongoDB.

Root cause: PyMongo decodes BSON dates as timezone-naive by default (no `tz_aware=True` on
`mongo.init_app()`). `_relative_time()` subtracts that naive timestamp from a tz-aware
`datetime.now(timezone.utc)`, which raises `TypeError`; the blanket `except Exception` swallows
it into the "unknown" fallback. mongomock preserves tzinfo without a BSON round-trip, so the
entire test suite is structurally blind to this path.

Fix strategy (both layers, decided below): defensively normalize naive datetimes inside
`_relative_time()` (covers ALL naive inputs regardless of driver/mock config — the primary,
test-covered fix), AND pass `tz_aware=True` to `mongo.init_app()` so real reads decode as aware
at the source. This restores the FEED-01 Event-Row Anatomy relative-time element.

Purpose: FEED-01's "2 minutes ago"-style relative-time cell must render real values against the
real MongoDB this phase's own DEP-03 work stands up — not silently degrade to "unknown".
Output: normalization guard in events.py, tz_aware=True in __init__.py, one regression test.

## Fix Decision (recorded per gap-closure requirement)

**Chosen: BOTH layers.**

- **Primary (defensive, test-covered): normalize inside `_relative_time()`.** A guard that
  converts a naive `ts` to UTC-aware (`ts.replace(tzinfo=timezone.utc)`) before the subtraction
  protects against every naive-datetime source — real PyMongo, a future direct DB write, a
  caller passing `datetime.utcnow()`. This is the robust option and is the one the mongomock
  regression test can exercise directly (mongomock cannot reproduce the BSON round-trip, so a
  source-only fix would be untestable in the suite).
- **Complementary (source): `tz_aware=True` on `mongo.init_app()`.** Fixes decode at the driver
  so downstream code (feed sorting, any future ts consumer) sees aware datetimes from real Mongo.
  Cheap, correct, aligns app behavior with what the tests already assume (aware timestamps).

The normalization guard is what the regression test asserts; `tz_aware=True` closes the source.
Doing both means the fix holds even if one layer is later changed.
</objective>
