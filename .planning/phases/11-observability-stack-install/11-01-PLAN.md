Then `set -o errexit` (NO pipefail — keep the same comment as cluster-setup.sh explaining why), `export MSYS_NO_PATHCONV=1`, and `KCTX='--context=kind-kind'`.

    Prerequisite gate: `for tool in docker kubectl helm; do command -v "$tool" ... exit 1; done` plus a `docker info` running-daemon check — copy the cluster-setup.sh fail-fast shape and add `helm` to the tool list.

    Step 0 — preflight capacity check (D-10): read node allocatable memory via `kubectl ${KCTX} get nodes -o jsonpath='{.items[0].status.allocatable.memory}'`, sum existing pod memory requests across all namespaces via `kubectl ${KCTX} get pods -A -o jsonpath` (kubectl JSONPath range, no jq dependency — follow the project's established JSONPath convention), and compare `(allocatable - existing_requests)` against the trimmed stack's total memory requests (sum of the requests in values-trimmed.yaml: 100Mi operator + 256Mi prometheus + 128Mi grafana + 32Mi kube-state-metrics). If headroom is insufficient, abort with an actionable Windows/Docker-Desktop message naming the exact setting to change: "raise Docker Desktop's memory allocation (Settings > Resources > Memory) to at least <N> GB and retry", then `exit 1`. Normalize Ki/Mi units before comparing.

    Step 1 — `helm repo add prometheus-community https://prometheus-community.github.io/helm-charts >/dev/null 2>&1 || true` then `helm repo update prometheus-community` (idempotent repo registration).

    Step 2 — `helm upgrade --install kube-prometheus-stack prometheus-community/kube-prometheus-stack --version 87.16.1 --namespace observability --create-namespace -f infra/observability/values-trimmed.yaml --wait --timeout 300s` (natively idempotent; no `--atomic`; longer 300s timeout than the apps' 180s because this is a first-time CRD install + multi-pod rollout).

    Step 3 — readiness self-check: wait for the long-running observability pods to be Ready. Note the chart also creates a short-lived admission-webhook patch Job whose pod reaches `Succeeded` (not `Ready`), so a bare `kubectl wait --for=condition=Ready pod --all` will trip on it — scope the wait to exclude Succeeded pods (e.g. `kubectl ${KCTX} wait --for=condition=Ready pod --all -n observability --field-selector=status.phase!=Succeeded --timeout=180s`). On failure, `kubectl describe` the not-ready pods and `exit 1` (self-verify-over-exit-code, matching cluster-setup.sh Step 6).

    Step 4 — additive-only re-verification (D-06): run `make smoke` then `make smoke-launchpad`. errexit halts the script if either fails, signalling the v1.1 apps were disturbed. End with `echo "==> observability-up complete."` plus printed port-forward hints for Prometheus (`svc/kube-prometheus-stack-prometheus 9090:9090`) and Grafana (`svc/kube-prometheus-stack-grafana 3000:80`).
  </action>
