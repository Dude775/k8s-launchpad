  <name>Task 2: Human verification — Prometheus + Grafana UIs reachable via port-forward</name>
  <what-built>
    The trimmed kube-prometheus-stack is installed in the `observability` namespace (re-install it
    with `bash scripts/observability-up.sh` if Task 1 already tore it down). Success criterion 4
    (UIs reachable via port-forward) and the D-07/D-08 Grafana access decisions require a human eye
    on a browser — this is the only part of the phase a CLI cannot fully assert.
  </what-built>
  <how-to-verify>
    1. Port-forward Prometheus: `kubectl --context=kind-kind -n observability port-forward svc/kube-prometheus-stack-prometheus 9090:9090` and open http://localhost:9090 — the Prometheus UI loads.
    2. Visit http://localhost:9090/targets — confirm there are NO down/red scrape jobs for `kube-etcd`, `kube-scheduler`, `kube-controller-manager`, `kube-proxy`, `alertmanager`, or `node-exporter` (they are disabled, so they must be entirely absent, not red).
    3. Port-forward Grafana: `kubectl --context=kind-kind -n observability port-forward svc/kube-prometheus-stack-grafana 3000:80` and open http://localhost:3000 — the Grafana login page loads.
    4. Log in as `admin` / `grafana-dev-password` (D-07) — login succeeds.
    5. Open an incognito window to http://localhost:3000 without logging in — confirm anonymous Viewer access works (D-08): you can browse but the UI shows a Viewer (read-only) role, no edit/admin controls.
  </how-to-verify>
