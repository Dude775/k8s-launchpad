## What happened

During the live verification run, `make cluster-up` was started as a background task. While `registry:3` was being pulled, the executor ran concurrent diagnostic docker commands (`docker logs`, `docker inspect`, `docker rm -f kind-registry`, `docker container prune`) against the daemon mid-`docker run`. This deadlocked the Docker daemon; recovery attempts (killing dockerd inside the docker-desktop WSL2 VM, manual nsenter restarts) cascaded into the WSL2 service crashing with `Wsl/0x80070422`.

**The scripts from Plan 02-01 (`cluster-setup.sh`, `cluster-teardown.sh`, Makefile targets) are correct** — reviewed line-by-line pre-crash. The failure was executor interference, not a script bug. No kind cluster was ever created; no repo files were affected.

## Critical Anti-Patterns

| Anti-pattern | Severity | What happened | Structural prevention |
|--------------|----------|---------------|----------------------|
| Concurrent docker CLI commands while a docker-driving script runs | blocking | Diagnostics (`docker logs/inspect/rm -f/prune`) ran against the daemon during `cluster-setup.sh`'s `docker run -d registry:3`, deadlocking the daemon | Run `make cluster-up` in the FOREGROUND with a 600000 ms Bash timeout and issue ZERO docker/kind commands until it returns. If it appears slow, wait — first run legitimately takes minutes (image pulls). Diagnose only AFTER the command exits. |
| Escalating daemon recovery inside the docker-desktop WSL2 VM | blocking | Killing dockerd/containerd-shim via `wsl -d docker-desktop` + nsenter crashed containerd and then the whole WSL2 service | Never kill dockerd/containerd processes inside the docker-desktop VM. If the daemon hangs: stop, record state, and return a human-action checkpoint asking the user to restart Docker Desktop. |
