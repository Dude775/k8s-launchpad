<objective>
Hand-write a single Helm chart (`charts/field-guide-api/`) that deploys the field-guide API and an in-cluster MongoDB. The chart uses `apiVersion: v2` (Helm-3 compatible; installed CLI is Helm 4.2.1), ships a generic `values.yaml` (the PRD-3 templating seam), injects `MONGO_URI` via a Secret and non-secret config via a ConfigMap, and embeds MongoDB as plain `mongo:7` manifests (Deployment + Service + chart-owned PVC + Secret — NOT a StatefulSet, NOT Bitnami) so `helm uninstall` removes everything cleanly.

Purpose: Satisfies HELM-01 (chart with Deployment/Service/ConfigMap/Secret/values, `helm lint` passes), HELM-03 (plain mongo:7 in-cluster), and HELM-04 (generic values.yaml). The chart is deployed and smoke-tested live in 03-04.
Output: A complete chart at `charts/field-guide-api/` replacing the `.gitkeep`.
</objective>

<!-- Contracts the templates must satisfy. Extracted from app source + RESEARCH.md. -->
- App env contract (`app/config.py`): reads `MONGO_URI` (contains password → Secret only), `MONGO_DBNAME` (→ ConfigMap), `FLASK_DEBUG` (→ ConfigMap; empty string = disabled, which is safe/required in-cluster).
- Readiness endpoint (`app/routes/health.py`): `GET /health` returns 200 `{"status":"ok","mongo":"up"}` when Mongo reachable, 503 within ~2s otherwise. This is the readinessProbe target — NEVER the livenessProbe (it would restart healthy pods during a Mongo outage).
- App container port: 8000 (gunicorn bind from the Dockerfile in 03-01).
- Canonical MONGO_URI (RESEARCH.md Pattern 4, live-verified vs mongo:7 + PyMongo 4.13.2): `mongodb://<user>:<pass>@<mongodb-fullname>:27017/<database>?authSource=admin`. The DB name MUST stay in the URI path (Flask-PyMongo derives `mongo.db` from it) and `?authSource=admin` MUST be appended (root user lives in `admin`). Omitting either breaks every entries route.
- Release name for this project is `field-guide-api` (fullname helper collapses to `field-guide-api`; mongodb resources become `field-guide-api-mongodb`).
- Verbatim source templates: RESEARCH.md Pattern 3 (values.yaml), Pattern 4 (secret.yaml), Pattern 5 (probes), Code Examples (deployment env + securityContext). Pitfall 9 (single-source-of-truth hostname helper). Pitfall 7 (PVC storageClass "").

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| values.yaml (repo) → git | Credentials in values.yaml would be committed; only a labeled dev default is allowed |
| app pod → mongodb pod | MONGO_URI (with password) crosses via a Secret; must never land in ConfigMap or image |
| cluster → outside | Services are ClusterIP; nothing exposed without explicit port-forward |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Information Disclosure | values.yaml credentials | mitigate | Only the clearly-labeled `fieldguide-dev-password` dev default lives in values.yaml with a "never a real credential — override with --set" comment; real creds via `--set`/`-f` |
| T-03-05 | Information Disclosure | MONGO_URI (contains password) | mitigate | URI rendered ONLY in `templates/secret.yaml` via `stringData`; never in ConfigMap, Deployment env literal, image, or NOTES.txt |
| T-03-06 | Elevation of Privilege | mongodb exposure | mitigate | mongodb Service is ClusterIP :27017; no NodePort/hostPort — reachable only inside the cluster |
| T-03-07 | Elevation of Privilege | app container privileges | mitigate | Deployment securityContext `runAsNonRoot: true`, `runAsUser: 10001`, `allowPrivilegeEscalation: false` |
| T-03-SC | Tampering | mongo:7 image provenance | accept | `mongo:7` is a Docker official library image (approved in RESEARCH.md Package Legitimacy Audit); no language-registry packages installed by the chart |
</threat_model>
