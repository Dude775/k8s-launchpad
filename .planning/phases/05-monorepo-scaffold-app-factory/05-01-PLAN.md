## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local filesystem → Docker build context | `.env` / kubeconfig could leak into the image if the build context is not scoped |
| app.k8s → Kubernetes config loaders | loader failure (no config) must fail closed to (None,None), not raise/leak cluster errors |

Phase 5 is a local scaffold: no external network exposure, no auth surface, no user
input beyond a static `/health` route, no secrets handled by app code. ASVS V2–V6
are all Not-Applicable this phase (RESEARCH §Security Domain).

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Information Disclosure | `apps/launchpad/Dockerfile` build context | mitigate | Own `.dockerignore` excludes `.venv/`, `tests/`, `__pycache__`, `.env`; Dockerfile uses an explicit COPY allowlist (`app/`, `wsgi.py`) — never `COPY . .` |
| T-05-02 | Repudiation | `app/k8s.py` config loaders | mitigate | Catch `ConfigException` narrowly per loader, never `except Exception` — silent-failure masking of real bugs is prevented; loader failure returns (None,None) (fails closed, leaks nothing) |
| T-05-03 | Information Disclosure | new app `.env` / kubeconfig in git | mitigate | Root `.gitignore` already pattern-covers `.env`, `.env.*`, `.venv/`, `kubeconfig`, `*.kubeconfig`, `.kube/` repo-wide (verified) — new app files inherit coverage; no per-app gitignore needed |
