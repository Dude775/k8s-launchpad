<objective>
Build the shared platform-status aggregation helper and the three consumer routes: the new
`GET /api/status` JSON endpoint (STAT-01/02), the evolved HX-Request-aware `/partials/status-cards`
fragment with real per-metric cards, and a verification test proving `/metrics` parity with
field-guide-api (STAT-04). A single `get_platform_status()` helper feeds both the JSON and HTML
representations so they can never drift.

Purpose: STAT-01/02 require real platform status (own-Mongo status, field-guide-api reachability,
version, service count) surfaced as JSON and rendered into dashboard cards, degrading gracefully
(never a 500) when field-guide-api is unreachable. STAT-04 requires /metrics to match field-guide-api's
Prometheus exposition — already wired since Phase 5, so this is a parity/coverage task, not new wiring.

Output: `app/status.py` (get_platform_status), `app/routes/status.py` (/api/status), an updated
partials route + `status_full_page.html` + rewritten `status_cards.html` template, a registered
status_bp, and mocked-requests unit tests covering every branch (mongo up/down, field-guide
reachable/unreachable, HX-Request present/absent, /metrics parity).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| launchpad → field-guide-api | Outbound cross-cluster HTTP GET to field-guide-api's /health over ClusterIP DNS; the target URL is server-configured, never client-supplied |
| browser → /api/status, /partials/status-cards | Read-only GET endpoints; no request body or query params consumed |
| Flask route → launchpad MongoDB | Own-DB ping + count_documents({}) with an empty (fixed) filter — no user input reaches any query |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-05 | Tampering / Information Disclosure | SSRF via a user-controlled reachability target URL | mitigate | FIELD_GUIDE_BASE_URL is sourced exclusively from current_app.config (env/ConfigMap) — no route in this plan accepts a URL parameter; documented so a future "configurable target" feature triggers review before reintroducing SSRF risk |
| T-07-06 | Denial of Service | requests.get to field-guide-api hanging the sole gunicorn worker | mitigate | mandatory timeout=2 on every requests.get (RESEARCH Pitfall 2); the grep gate in Task 1 acceptance criteria enforces the timeout keyword |
| T-07-07 | Information Disclosure | verbose error leakage in /api/status or the status fragment | mitigate | get_platform_status() except blocks discard exception detail and return fixed-shape degraded values ("down", False) — never str(exception); no hostname/stack-trace/connection-string reaches the JSON or HTML |
| T-07-08 | Tampering | NoSQL injection via query construction | accept | only fixed operations introduced (admin.command("ping"), count_documents({}) with an empty filter); no user input reaches any Mongo query this plan; documented precedent for Phase 9's user-input-driven queries |
| T-07-09 | Denial of Service | Mongo ping in get_platform_status() blocking the worker | mitigate | reuses Plan 01's serverSelectionTimeoutMS=2000 binding — bounds the ping to ~2s |
</threat_model>
