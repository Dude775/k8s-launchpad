<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| launchpad pod → Kubernetes API | The pod's ServiceAccount identity is what the K8s API authorizes; over-grant here is a privilege risk |
| chart Secret → pod env | MONGO_URI must reach the pod only via a Secret, never a ConfigMap or plaintext literal |
| two charts in one namespace | field-guide-api and launchpad Services must not cross-select each other's pods |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Elevation of Privilege | rbac.yaml Role scope | mitigate | Namespace-scoped `Role` (NEVER `ClusterRole`), verbs limited to `get`/`list`/`watch` on `pods`+`deployments` only (SC #4 / DEP-02). helm template asserts no `kind: ClusterRole`. |
| T-08-02 | Information Disclosure | secret.yaml / deployment env | mitigate | `MONGO_URI` sourced only via `secretKeyRef` from the chart Secret; never a ConfigMap key or plaintext env literal. Placeholder URI is a local-dev value, never a real credential. |
| T-08-03 | Spoofing / mis-routing | _helpers.tpl selectorLabels | mitigate | Distinct `app.kubernetes.io/name: launchpad` prevents the field-guide-api Service selector from matching launchpad pods and vice versa (SC #1). helm template asserts the output never emits `app.kubernetes.io/name: field-guide-api`. |
| T-08-04 | Tampering (image supply chain) | manual docker build / kind load | mitigate | Image built locally from `./apps/launchpad` and loaded into kind or pushed to the local `localhost:5001` registry — no external image pull. No registry-package installs occur in this plan. |
| T-08-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs in this plan — the chart is authored from an existing analog; the app image reuses already-pinned requirements. RESEARCH §Package Legitimacy Audit: not applicable. |
</threat_model>
