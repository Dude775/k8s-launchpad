<objective>
Prove the full local cluster lifecycle end-to-end on a live machine: `make cluster-up`
creates a kind cluster with a wired `registry:3` and self-verifies a push+pull-from-pod,

to re-run. This satisfies the STATE.md research flag ("verify registry wiring with a test
image pull from within the cluster before proceeding to Phase 3") and all three Phase 2

scripts. CLUS-01 and CLUS-02 are only truly satisfied when the loop runs on real Docker/kind.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Elevation of Privilege | live registry port exposure | mitigate | Verified at runtime: registry bound to `127.0.0.1:5001` (from 02-01 setup); check `docker port kind-registry` shows only `127.0.0.1` if exposure is in doubt |
| T-02-02 | Information Disclosure | kubeconfig written by `kind create cluster` | mitigate | `kind` writes to `~/.kube/config`; `.gitignore` covers `kubeconfig`/`.kube/`; run `git status` after cluster-up to confirm no kube artifacts are staged |
| T-02-05 | Spoofing | kind binary provenance during install | mitigate | Install only via official `winget` package `Kubernetes.kind` or the official kind.sigs.k8s.io download URL; no third-party mirrors |
| T-02-SC | Tampering | images pulled at runtime (`registry:3`, `kindest/node:v1.36.1`, `alpine:3.20`) | mitigate | All official images per RESEARCH Package Legitimacy Audit; no package-manager installs — nothing to slopcheck |
</threat_model>
