    `export MSYS_NO_PATHCONV=1` (suppresses Git Bash path mangling of `-p "127.0.0.1:5001:5000"`
    and `/dev/stdin`). Define `reg_name='kind-registry'` and `reg_port='5001'`.
    Prerequisite gate first: if `command -v kind` fails, echo an error plus the install line
    `winget install Kubernetes.kind` and the binary URL, then `exit 1`.
    Step 1 — registry: only `docker run` if `docker inspect -f '{{.State.Running}}'` is not `true`;
    run detached, `--restart=always`, `-p "127.0.0.1:${reg_port}:5000"` (127.0.0.1 ONLY — never
    0.0.0.0, this is the security control), `--network bridge`, `--name "${reg_name}"`, image
    `registry:3`.
    Step 2 — cluster: only `kind create cluster --config infra/kind/kind-config.yaml` if
    `kind get clusters | grep -q '^kind$'` is false (anchored match on the exact name `kind`).
    Step 3 — hosts.toml: `REGISTRY_DIR="/etc/containerd/certs.d/localhost:${reg_port}"`; loop over
    `$(kind get nodes)`, `docker exec` mkdir the dir, then pipe a heredoc whose single line is
    `[host."http://${reg_name}:5000"]` into `docker exec -i "${node}" cp /dev/stdin
    "${REGISTRY_DIR}/hosts.toml"`. The key MUST be `http://kind-registry:5000` (inner container
    name + port 5000), NOT localhost:5001 — getting this wrong causes silent ImagePullBackOff.
    Step 4 — network: connect `kind-registry` to the `kind` network only if
    `docker inspect -f='{{json .NetworkSettings.Networks.kind}}'` equals `null`.
    Step 5 — discovery: `kubectl apply` a ConfigMap `local-registry-hosting` in namespace
    `kube-public` with `localRegistryHosting.v1` host `localhost:${reg_port}`.
    Step 6 — verification (STATE.md research flag, blocking): `docker pull alpine:3.20`,
    tag+push `localhost:5001/verify:v1`, `kubectl run registry-verify
    --image=localhost:5001/verify:v1 --restart=Never --image-pull-policy=Always -- echo
    "registry-ok"`, `kubectl wait --for=condition=Completed pod/registry-verify --timeout=60s`,
    `kubectl delete pod registry-verify --ignore-not-found`, and a final "Registry wiring verified
    OK" echo. `--image-pull-policy=Always` forces a real pull, not a cache hit.
    Do NOT add `set -o pipefail` — it conflicts with the `... || true` idempotency guards.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host → local registry | Images pushed from the developer host to `localhost:5001` (unauthenticated) |
| cluster pod → registry | Pods pull images over the `kind` docker network via `kind-registry:5000` (HTTP) |
| host filesystem → git | Cluster credentials (`~/.kube/config`) must never enter the repo |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Elevation of Privilege | `registry:3` container port binding | mitigate | `docker run -p "127.0.0.1:5001:5000"` — loopback only, never `0.0.0.0`; enforced by verify grep `! grep -q '0.0.0.0'` |
| T-02-02 | Information Disclosure | kubeconfig credentials | mitigate | `kind` writes to `~/.kube/config` (system path, not repo); `.gitignore` already covers `kubeconfig`, `*.kubeconfig`, `.kube/` — no repo write in this plan |
| T-02-03 | Information Disclosure | HTTP node→registry traffic | accept | HTTP is intentional over the loopback-scoped `kind` docker network; `hosts.toml` uses `http://kind-registry:5000` by design; no external exposure |
| T-02-04 | Tampering | image content in local registry | accept | Local single-user dev registry; only the developer pushes; acceptable per RESEARCH Security Domain |
| T-02-SC | Tampering | container images pulled (`registry:3`, `kindest/node`, `alpine:3.20`) | mitigate | All official images per RESEARCH Package Legitimacy Audit; no npm/pip/cargo installs in this phase — nothing to slopcheck |
</threat_model>
