  <action>
    Create `apps/field-guide-api/Dockerfile` as a two-stage build. Builder stage: `FROM python:3.11-slim AS builder`, `WORKDIR /build`, `COPY requirements.txt .`, then `pip install --no-cache-dir --prefix=/install -r requirements.txt`. Runtime stage: second `FROM python:3.11-slim`, set `ENV PYTHONDONTWRITEBYTECODE=1` and `PYTHONUNBUFFERED=1`, `WORKDIR /app`, `COPY --from=builder /install /usr/local`, then COPY ONLY `app/ ./app/` and `wsgi.py .` (explicit allowlist — never a broad `COPY . .`). Create a numeric non-root user with `groupadd -r -g 10001 app` and `useradd -r -u 10001 -g app app`, then `USER 10001` (numeric so Kubernetes `runAsNonRoot` is kubelet-verifiable). `EXPOSE 8000`. Final directive is an exec-form (JSON-array) `CMD` running gunicorn bound to `0.0.0.0:8000` with `--workers 1 --threads 4`, `--access-logfile -`, `--error-logfile -`, and target `wsgi:app`. Exec form is mandatory so gunicorn is PID 1 and receives SIGTERM directly (shell form would put `/bin/sh` at PID 1 and swallow SIGTERM → 30s force-kill on every rollout). `--workers 1` is mandatory (multiple workers corrupt prometheus-flask-exporter metrics). The build context is the directory `apps/field-guide-api` (so `COPY requirements.txt .` and `COPY app/` resolve relative to it). Start the file with a purpose + source-citation header comment in the repo's convention. NEVER reference the Flask dev server or `flask run`; NEVER add `ENV FLASK_DEBUG`.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host build context → image layers | Files on the Windows host cross into the Linux image at COPY time (venv binaries, secrets could leak in) |
| image runtime → cluster node | The container process runs on the kubelet's node; a root process is an escalation surface |
| Docker Hub → local build | Base image `python:3.11-slim` is pulled from an external registry (supply chain) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Elevation of Privilege | runtime container user | mitigate | `groupadd/useradd` UID 10001 + `USER 10001` numeric directive; chart (03-02) adds `runAsNonRoot: true` to enforce at kubelet |
| T-03-02 | Tampering / supply chain | Docker build context | mitigate | `.dockerignore` excludes `.venv/`; Dockerfile COPYs only `app/` + `wsgi.py` (explicit allowlist) — no Windows `.pyd` binaries baked in |
| T-03-03 | Information Disclosure | Flask debug in image | mitigate | Dockerfile sets NO `FLASK_DEBUG` ENV; debug stays opt-in via ConfigMap (defaults empty/disabled) |
| T-03-SC | Tampering | base image + pip installs | accept | No new PyPI packages this phase (requirements.txt unchanged, audited in RESEARCH.md Package Legitimacy Audit). Base `python:3.11-slim` is a Docker official library image (approved, locked in CLAUDE.md). No `[ASSUMED]`/`[SUS]` packages → no blocking checkpoint required. |
</threat_model>
