<objective>
Build the field-guide Flask API as an application factory backed by MongoDB, exposing the entries CRUD endpoints, a MongoDB-aware `/health` readiness endpoint, and a Prometheus `/metrics` scrape seam. Everything reads config from the environment; no secrets or connection strings are hardcoded. The app is served through a gunicorn WSGI entrypoint from day one — the Flask dev server never appears in a runnable production path.

Purpose: This is the platform's dogfood application. It must run locally now (backed by a local MongoDB via env-supplied URI) and later unchanged inside the kind cluster (backed by an in-cluster mongo:7 via a Kubernetes Secret). Building it as a factory with env-driven config is what makes both contexts work from the same code.
Output: A fully working `apps/field-guide-api/` Flask package plus pinned `requirements.txt` and a `.env.example` template.
</objective>

<interfaces>
<!-- Contracts this plan establishes. Plan 03 (tests) implements against these. -->

Entry document shape (MongoDB collection `entries`):
```
{
  "_id": ObjectId,          # serialized to string "id" in responses
  "title": str,             # required on POST
  "category": str,          # optional, defaults to "general"
  "content": str,           # required on POST; markdown body
  "tags": [str],            # optional, defaults to []
  "created_at": str         # ISO-8601 UTC timestamp, server-generated
}
```

Endpoint contracts:
```
GET  /entries          -> 200 [ {id,title,category,content,tags,created_at}, ... ]
GET  /entries/<id>     -> 200 {id,...} | 404 {"error": "..."} (invalid ObjectId also 404)
POST /entries          -> 201 {id,...} | 400 {"error": "..."} when title/content missing
GET  /health           -> 200 {"status":"ok","mongo":"up"} | 503 {"status":"unavailable","mongo":"down"}
GET  /metrics          -> 200 Prometheus text (Content-Type text/plain; version=0.0.4)
```

Factory contract (used by wsgi.py and tests):
```
from app import create_app
app = create_app(config_overrides=None)   # dict overrides for TESTING/MONGO_URI
```

Extension singletons (app/extensions.py):
```
mongo = PyMongo()                          # flask_pymongo
metrics = PrometheusMetrics.for_app_factory()   # prometheus_flask_exporter
```
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| environment/config → application | MongoDB connection string and debug flag cross here; must be env-supplied, never hardcoded |
| HTTP client → API | Untrusted request bodies and path params (entry id, POST payload) enter here |
| application → MongoDB | Query construction boundary; injection risk if queries built from raw strings |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | config.py / MongoDB URI | mitigate | `MONGO_URI` read only from `os.environ`; `.env.example` holds a placeholder, real `.env` is gitignored (Plan 01); no literal credentials in source |
| T-02-02 | Elevation of Privilege | Flask debug mode | mitigate | `DEBUG` derived from `FLASK_DEBUG` env, defaults False; app served via gunicorn `wsgi:app`, Flask dev server never in a runnable container path (CLAUDE.md) |
| T-02-03 | Tampering / Injection | POST /entries body, /entries/<id> | mitigate | Required-field validation returns 400; queries passed as Python dicts to PyMongo (no string-built queries); `ObjectId()` wrapped in try/except returning 404 on malformed input (no 500 leak) |
| T-02-04 | Denial of Service | GET /entries unbounded scan | accept | Single-user local foundation, dataset trivial; pagination deferred (documented as out-of-scope over-engineering in REQUIREMENTS.md) |
| T-02-SC | Tampering (supply chain) | pip runtime dependencies | mitigate | All six packages pinned to exact versions verified against official PyPI/Context7 sources in CLAUDE.md "Sources" (HIGH confidence); no unvetted or typosquat packages introduced |
